# 指标与验收规范 v1

此规范在看结果前固定；改变定义时记录原因与前后差异。

## 时间和数据质量

timestamp 按毫秒解析，统一 UTC。源网站时区未知，UTC 小时分布不解释为本地用户作息。原始表只读保留行号。核心字段 timestamp/visitorid/itemid/event 缺失或解析失败隔离记录；浏览或加购的 transactionid 为空正常。

对五字段完全重复记录先统计，主分析可保留一个副本，但同时做保留全部的敏感性。没有独立 event_id 时不能保证完全相同记录一定是埋点重复；不按“同用户同一行为”删除正常重复浏览。原始计数=合法计数+隔离计数；合法计数=去重后计数+被标记重复计数。

## 主漏斗定义

- 单位：同一 `(visitorid,itemid)` 对；一个访客可贡献多个商品对，不称为“用户转化率”。
- 入组锚点 t0：该商品对在日志中的第一次 view。不是注册时间、首次访问全站时间或首次真正看过该商品。
- 共同入组队列：t0 不晚于全数据最大事件时间减 7 天，统一供 1h/24h/7d 比较，防止不同分母混淆。
- W 为 1 小时、24 小时或 7 天，均指 t0 到最终事件的总时长，不是每步各 W。
- t1：相同访客商品对中最早满足 `t0 < addtocart_ts <= t0+W` 的加购。
- t2：相同访客商品对中最早满足 `t1 < transaction_ts <= t0+W` 的成交。
- 分母 N0：共同入组队列的商品对数。
- 加购阶段 N1：有合法 t1 的商品对数。
- 经加购成交 N2：有合法 t1 和 t2 的商品对数。
- 浏览到加购率=N1/N0；加购到成交率=N2/N1；经加购全程转化=N2/N0。分母 0 时为 NULL/不可估计，不填 0 冒充观测。
- 相同时间戳采用严格 `>`：无可靠顺序证据时不补造先后。附录另报受影响量；选做 `>=` 宽松口径对照并说明差异。

固定“首次浏览锚点”会漏计更晚再次浏览才开启的某些路径。这是明确的队列定义，不等于全站所有购买机会。可选会话漏斗用于比较，不与主口径混报。

## 辅助口径

1. 行为覆盖：全观察期做过各类行为的独立访客数。它可以不嵌套，人数比值不称严格漏斗转化。
2. 浏览后成交：同一锚点下最早满足 `t0 < transaction_ts <= t0+W`，不要求加购。标记“在观测数据中未出现有效加购”，不断言用户真实跳过购物车。
3. 访客级：从合格商品对聚合到访客，一位访客任意合格商品对完成即计一次，分母为有合格商品对的访客。不要直接把商品对转化率当作访客转化率。
4. 交易量：transaction 事件行数、不同 transactionid 数、成交商品对数分别报告；都不直接写为 GMV。
5. 进入周：按 t0 的 UTC 日期或周归属，不能用同日浏览人数去除同日全部成交人数当队列转化。
6. 历史行为分组：在 t0 前存在更早全站事件的访客，与“数据中首次观测访客”比较。前者可以叫已有观测历史，后者不能叫注册新客；标注日志起点左截断。

涉及主报告 7 天窗口时，末 7 天进入者不记为流失。若额外展示每个窗口各自最大可用队列，必须单独画图，并标明分母不同。

## 分层和不确定性

分层属性在进入时固定，不能使用未来成交次数、全月活跃度定义“高价值用户”再解释其转化更高。历史浏览量或商品热度仅使用 t0 前数据，必要时采用 7 天回看并标注初期历史不足。

每个分组必须给出 N0、N1、N2。默认把分母不足 100 或目标成交不足 10 的组标为探索性，阈值是报告展示规则，不是统计有效性的保证。主报告不对几十个小组排名后声称找到最优原因。

商品对共享访客，不满足逐行独立假设。不对商品对直接套普通二项独立区间。若做区间，用访客簇 Bootstrap；如果只做点估计，则明确为描述性结果并做跨周稳定性比较。观察性分层差异不等于因果作用。

## 必测的小路径用例

以下每例是单独商品对，除特别说明外窗口 24h、观察完整。用自己写的测试数据验证：

| 用例 | 路径 | N0/N1/N2 贡献 |
|---|---|---|
| 正常 | view 10:00 → cart 10:10 → buy 10:20 | 1/1/1 |
| 先加购后浏览 | cart 09:00 → view 10:00，无后续 | 1/0/0 |
| 早期加购干扰 | cart 09:00 → view 10:00 → cart 10:10 → buy 10:20 | 1/1/1；不能只取全局最早 cart |
| 早期成交干扰 | view 10:00 → buy 10:05 → cart 10:10 → buy 10:20 | 1/1/1；后一次成交有效 |
| 错序且无后续成交 | view 10:00 → buy 10:05 → cart 10:10 | 1/1/0；辅助浏览成交可计 |
| 跨商品 | view A → cart B → buy B，B 无 view | A 贡献 1/0/0；B 不入组 |
| 相同时间戳 | view/cart/buy 均 10:00 | 1/0/0；另记歧义 |
| 重复行为 | 多次 view、cart、buy | 同商品对每阶段最多计一次 |
| 窗口边界 | cart 在 t0+1h，buy 在 t0+24h | 24h 口径 1/1/1 |
| 超出窗口 | cart t0+1h，buy t0+24h+1ms | 24h 口径 1/1/0 |
| 尾部截尾 | 首次 view 距数据最大时间仅 2 天 | 从共同 7 天可观测队列排除，不算流失 |
| 无 view | 只有 cart/buy | 不入主漏斗，单独报告日志覆盖现象 |

全量不变量：0<=N2<=N1<=N0；同队列 W 变大时 N1、N2 不应下降；严格路径成交商品对不超过浏览后成交商品对；SQL 与人工及 Pandas 小样本一致。对固定同队列与严格定义验证，不强行要求“行为覆盖人数”也递减。

## 优先级与建议

环节的流失人数与流失率分开比较。高流失率不自动意味着最值得优化；需要考虑触达量、下一步到成交的比例、实施成本及可验证性。若做潜在收益情景，只报告“假设环节转化增加 X 时的模拟成交对变化”，不把假设写成已经实现或已被预测模型证实的增长。
